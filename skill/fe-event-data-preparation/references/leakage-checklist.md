# 泄漏检查清单（leakage checklist）

用法：动手**前**走一遍确定协议，动手**后**再走一遍才允许报分数。每条都是二元判断，
勾选时把"证据在哪一行/哪个文件"写进运行记录，写不出证据就是没做。

## A. 样本构造

- [ ] 预测锚点（anchor）只来自事件或固定时间网格：出现"以告警时刻生成正样本"即为协议违规，
      因为告警就是标签本身，用它定义样本等于用标签划样本，正负两类的构造机制会天然不对称。
- [ ] 历史窗口严格截止到 anchor：任何特征用到 `event_time > anchor` 的行都是未来信息，
      包括"看起来只是聚合"的窗口统计。
- [ ] 排序按 prepare 之后的**带时区时刻**，不按原始字符串时间：字符串序会把时区后缀、精度与分隔符
      差异当成顺序，排完仍然乱，窗口算术随之静默偏移。
- [ ] 乱序输入是被拒绝、还是被一次可核对的外排序解决：读取器遇到跨块时刻倒退必须报错而不是丢行，
      排好的文件要留下独立产物与摘要，便于复核"样本顺序变了但行数没变"。
- [ ] 首故障之后的事件被剔除，并且剔除动作有计数（`post_failure_event`），不是静默丢掉。
- [ ] 每个候选样本都做了删失判定：`label_window_end` 超出该单元随访截止的一律丢弃并计入
      `censored`，禁止把"没观察到"当成"确认没发生"。
- [ ] 随访截止来源可核对：无告警单元没有工单行，它的覆盖终点必须来自可信静态来源，
      不能每台机器现编一个。
- [ ] 每单元行采样上限对正负两类**同样**生效，或者不对称被写进运行配置并说明后果；
      只裁多数类会制造协变量偏移，让"样本多少"本身成为特征。
- [ ] 软标签（衰减权重）改变的是分数尺度：使用软标签时阈值语义随之变化，
      同一分位阈值在两种目标函数下不可比，报告里必须写清当前是哪一档。

## B. 划分与评估

- [ ] train / dev / val 沿时间轴切，且段间 embargo 不小于 `lead + horizon`：
      随机按单元分组不等于时间外推，按单元分组只能保证同一台设备不跨段，
      它防得住身份泄漏、防不住"学到的是这个月而非劣化过程"。
- [ ] 划分边界写在配置文件里并被 manifest 记录：每次运行各自重算边界会让两次分数不可比。
- [ ] 审计结论决定运行是否算完成：`audit_temporal_splits` 不通过时 CLI 必须失败退出，
      不允许"警告着出分"。
- [ ] 阈值只来自训练期的 CV 或固定的告警预算分位：在评估集上扫阈值取最优 F1 是上帝视角，
      绝对分系统性偏乐观。
- [ ] 命中窗按官方口径判：告警必须落在 `[alarm - horizon, alarm - lead]` 内才算命中，
      把标签窗当命中窗会让分数虚高一个量级；严格口径与宽松口径并列报告，禁止只报上界。
- [ ] 同一单元多次告警的计法明确（重复计 / 只计首次 / 按次加权），并与评分实现一致；
      未读评分源码时该状态记为 provisional，不当已确认。
- [ ] 未评分样本单独计数：`unscored_n` 不为零时，召回率的口径要说明这些故障单元算不算漏报。

## C. 数据与产物

- [ ] holdout 与私有 test 标签没有被读取，也没有被打印、上传或写进任何产物；
      本地评估器是唯一给分渠道，外部榜单只作历史参考。
- [ ] 外部测试集没有被用于训练或早停；官方留作第二阶段的混合型号数据不是本阶段的验证集。
- [ ] 全数据统计编码（按标签聚合的 target encoding）不存在，或只用训练期折内统计。
- [ ] 日志、manifest、报告与 PR 描述里没有真实序列号、原始事件行、私有绝对路径与任何密钥值。
- [ ] 静态身份列（厂商、型号类）来自与标签无关的来源，其取值不携带故障信息。
- [ ] 协议变更后旧分数只作历史：换了锚点规则、删失规则或命中窗之后，新旧绝对分不得放进同一个
      "提升"叙事里比较。

## D. 判分与可信度

- [ ] 报分数时同时给：口径（哪把尺子）、数据规模、阈值来源、随访截止、未评分样本数。
- [ ] 指标异常先复核评估代码再怀疑模型：一次阈值下标比较错误能让整轮实验数字全部作废。
- [ ] 快速 fixture 上的通过不等于真实包可用：真实数据的首次运行必须验证目录假设、
      时刻乱序拒绝、空闲空间不足与缺项报错这几条拒绝路径。
