# 科研项目控制、恢复与证据沉淀

## 宿主维护的项目状态

项目元数据与引擎状态分开。`project.yaml` 定义问题、目标、输入、阶段预算和结果位置；`state.json` 记录当前阶段、活动 run/PID、完成工件、下一动作及阻塞原因；`decisions.jsonl` 记录每次研究决策；`steps.jsonl` 记录执行步骤；`runs.jsonl` 关联各 run 和外部 HPO；`costs.jsonl` 汇总去重的已知用量与未知项。格式起点见 `../assets/research-records.template.md`。

启动时读取已有记录、核对本地 run 状态及进程；只由一个宿主协调项目状态，写 JSON 用临时文件替换。引擎 run claim 保护单 run，不能宣称项目级多宿主分布式锁已经实现。宿主退出时保存下一步；没有宿主运行环境时，Skill 本身不会在后台自主执行。

## 决策循环

```text
读取项目契约、已完成工件、累计预算和现有实验
while 研究交付未完成 and 项目仍有授权预算:
    选择最早缺失的必要工件，生成并验证
    运行/接续一个有明确假设和边界的实验或 HPO 批次
    读取本地评价、原始证据、成本和失败事件
    判断同一候选的全部约束，并检查研究交付条件
    记录证据 → 决策 → 下一动作 → 剩余预算
    达到目标时停止搜索，完成预定复验和交付
    否则按下表执行有证据支持的修正
结束时发布当前最好证据、未解决问题及可恢复状态
```

| 观察证据 | 下一步行动 | 记录与边界 |
|---|---|---|
| 训练体检有阻断项，或数据语义不明 | 回到数据工作流，核对标签、关联和时间契约 | `ok=true` 只表示生成报告；解决核心问题前不派发受影响实验 |
| 缺依赖、超时、输出错误导致无效 | 修复执行/候选接口，必要时缩小单次成本 | 基础设施失败不当作算法性能下降；在预定重试额度内处理 |
| 未满足召回/FAR 等约束，排序已改善 | 优先校准、代价敏感方法或错例方向 | 训练内确定阈值，验证集不直接拿来拟合阈值 |
| 结构有效但数值选择粗糙 | 固定路线做 HPO | 保存参数空间和基准值，失败保留原候选 |
| 指标提高但模型成本越界 | 简化、特征删减、轻量结构方向 | 同时检查性能约束，不因提速单项优秀就通过 |
| 所有岛停滞、重复相似方案 | 补查相关文献、比较负经验，提出新假设并重配岛屿 | 记录差异；新 run 承接累计成本，不重置总预算 |
| 文献卡未注入/未采纳 | 检查路径、关键词、预算、算子和实际事件 | 修正可验证配置；不要把未执行假设当作失败证据 |
| val 与预定复验不一致 | 检查泄漏、切分和稳定性，降低结论强度 | 不挑种子或隐瞒失败实验；受保护数据不读取 |
| 数据/评估器不足或外部资源不可用 | 保存工件和精确缺口，推进不依赖它的工作 | 必要依赖未满足不能伪造运行或成绩 |
| 总预算耗尽或无法提出有依据的新动作 | 终止并报告未达标及原因 | “持续迭代”不等于无限执行或自行扩大预算 |
| 图表、摘要与节点/TrialLedger 数字不一致 | 核对候选、划分、运行身份并重新生成派生产物 | 暂停相应结论，不手改图表数据来对齐预期 |

未被当前问题触发的分支无需机械执行。每次决策都要引用节点、trial、文献或运行事件，并写可证伪的下一项假设。

## 预算与恢复规则

项目总预算覆盖文献/设计、代码进化、HPO、修复、复验及报告。引擎的 `budget` 仅管理其 run 内支出；宿主阶段和外部 HPO 在项目账本另计。把可用预算分成小批次，派发前核对余额，并为已派发调用的最大输出/超时预留余量。已发出的调用可能超出最后剩余额度，准确报告实际值。

模板中的 null 表示尚未确定，不代表无限预算。启动实际研究前从用户要求和既有授权落实有限总轮次/评估数、时间及可计量成本，记录分配依据；同一项目已有预算要求持续生效。缺少必要执行预算时先完成数据理解、文献与设计等可推进工作，再询问确实缺失的约束。

同时记录全项目墙钟时间、有效执行时间、Token 和完整评估/fit 数；计量未知则记录来源缺失，不能填零或假称严格 Token 熔断。无法计量宿主 Token 时说明引擎上限只覆盖引擎调用，以时间、请求次数和已知账单辅助管理预算。

用户给定的演化总额度跨所有岛和关联运行累计，不能为每岛或每个新 run 重置。引擎 HPO 槽可能计入轮次，外部 HPO trial 另外计数。参考运行的 15 轮和 24 次 HPO 只作为历史记录；新任务按本项目契约确定额度，不自动沿用或附加。

恢复相同 run 要保持目标、非预算配置、任务/数据/知识身份。当前 `fe research --resume` 允许显式 budget 更新并写 `research_intervention`；宿主日志还应区分是用户指令、预授权分批执行还是 AI 自主规划，不能把所有恢复统称人工。修改非预算配置时创建新 run 并记录 parent_run_id；评估口径变化则建立新的可比基线。耗时以原项目起点计算，首次达标跨完整历史重建。

## 自动化统计

预先在 `steps.jsonl` 确定适用步骤粒度和 planned_step_id，覆盖问题契约、数据、文献、结构/评估、配置、实验、HPO、验收、可视化和沉淀。相同计划步骤重试保留 attempt_id，不能为提高百分比拆出大量容易的 AI 子步骤。

- 已执行步骤自动化率 = 无运行中人工介入的已执行适用步骤数 / 已执行适用步骤总数。
- 全流程自动化完成比例 = 无运行中人工介入且已完成的计划适用步骤数 / 全部计划适用步骤数。
- 另列人工介入次数、触发原因、未执行/失败步骤以及计划变更理由。初始需求输入与运行中人工干预分开记录；AI 使用工具属 AI 执行，权限批准按人工介入留痕。
- 没有完整步骤日志时两项比例均未知，不能由“实验运行成功”推导 100%。单次引擎报告的 coverage=null 不会因增加 Skill 自动变成已统计。

## 最终证据与方法规范

按项目统一汇总四类证据：性能相对同口径基线的改进；实际模型复杂性及所有可计量 Token；自动化和首次达标轮次/耗时；多数据集效果与迁移对照。不同评分公式不平均，不把接口可迁移写成性能泛化。

对每条可复用经验记录“适用条件、操作、真实证据、已知失败情形、下一验证、版本”，关联来源 → 卡片 → 假设 → 岛屿 → 节点/参数 trial → 指标。导出最终 Skill 时保留通用流程，把本项目证据放 `references/project/`，不能把单个数据集的最佳超参数变成所有任务的默认标准。

成果包括数据质量和处理日志、文献综述/引用、研究设计、冻结配置和岛屿理由、决策与步骤记录、实验/HPO 指标、复杂性和成本、图表、可复用经验、报告和 Skill ZIP。默认先生成本地交付目录，按当前用户要求确定归档位置及候选代码范围。归档先枚举允许文件，排除密钥、原始/私有数据和活动数据库；源码未获准时只引用本地位置与哈希。生成文件清单与 SHA256，复制后校验，详细规则见 [结果与交付](results-and-delivery.md)。

## 行为验收场景

交付 Skill 前，用实际接口验证配置和入口，再依据以下输入检查应产生的工件与决策。文档审查只能证明覆盖规则，不能替代真实自主科研实验：

1. 只有科研问题：先形成目标和文献/任务结构；缺真实数据则标阻塞，不能启动伪真实实验。
2. 已有硬盘任务及明确的 15 轮短预算：复用评估器和知识，自动生成有限岛屿配置，正确选择 HPO 路径，保留该项目 15 轮总额度；其他项目不继承这个数字。
3. 内存/光放大器任务：验证适配器和数据，不能启用 HDD 专用 HPO 作为通用实现；需要桥接时先构建并小样本验证。
4. 最高评分候选违反 FAR/成本约束：选联合可行候选，若不存在则不达标；针对缺口继续。
5. 全岛停滞或恢复：引用失败证据调整路线/补文献，创建关联 run，累计预算和第一次基线不重置。
6. 用户只要 Skill 或要求仅归档结果：交付规范与模板，不启动付费任务，不移动工程源码。
7. 体检 `ok=true` 但 `quality_status=blocked`：读已生成证据并解决阻断项；没有 discovery_frames 的任务采用显式的任务专用检查，不造通过结论。
8. 可视化最高分与研究 selected 不同，或 HPO 胜出：按实际来源展示最终候选及联合约束，不能拿原树的最高分冒充最终验收。
9. 收到带 latest-result 的旧 Skill：核对实验身份，把旧成绩作为历史参考，不默认恢复、重跑或继承其模型/预算/归档目录。
