# 数据理解、处理与实验准入

核心 `fe run` 不强制处理数据。只有显式设置 `workflow.data.enabled: true` 才通过任务适配器执行可选处理；HDD 已实现完整训练文件检查、运行目录中的派生处理与复检，通过后再创建演化实验。工件包括 `data-workflow.json` 和 `data-checkup/{before,after}/`。当前自动处理仅支持完全重复历史行去重、无穷特征值转缺失；接受缺失/常量须写入配置。原始基准数据不修改。其他适配器仅在开启这一可选步骤时需要实现训练处理合同；关闭时可直接使用核心调优。

先读取任务的数据说明、评估接口和允许输入清单，理解每行代表设备、事件还是时间快照。记录字段含义、单位、采样方式、标签来源、预测窗口、时间与实体划分、业务误告/漏告代价；不能从字段名称猜测不明标签。数据文件不足时推进问题定义和文献，明确实际实验的依赖。

## 已有训练视图的聚合体检

独立只读命令 `fe data checkup` 默认从 `<任务目录>/evolve.yaml` 创建适配器，也可通过 `--config-file` 使用本次运行的有效配置；要求适配器实现 `discovery_frames(task_spec)`。HDD 已实现，不要假设所有 Famou/SmartMem 任务都有此能力。该命令检查适配器视图；完整原始训练检查与处理由统一工作流负责。

```bash
.venv/bin/python -m faultevolve.cli data checkup <任务目录> \
  --strict --json --out <项目目录>/data/checkup-before
```

- 退出 0：报告生成且无阻断项；仍须读取 `quality_status` 和处理建议。
- 退出 2：有阻断项，报告已经保存；读取证据并处理，不因 `ok=true` 就派发实验。
- 退出 1：读取或执行失败；先定位数据/适配器问题，不当成数据体检通过。

主要产物为 `data_facts.json`、`data_quality.json`、`field_coverage.csv` 和 `data_report.md`。质量状态 `blocked/review/ready` 分别表示阻断、需复核和当前已执行检查未发现问题。问题必须带计数、字段依据、处理建议；视图指纹用于复核输入，原始文件版本另行记录。

体检不自动清洗，不做功效估计；`min_detectable_effect=null` 不能补成默认数值。HDD 的发现视图可能已去重、截断历史和转换类型；报告不能代替原始文件质量、跨划分重叠、逐设备 cutoff 或标签生成验证。

若命令不适用于当前任务，在项目目录编写任务专用的只读体检脚本，按明确文件清单读取获准输入，输出同等用途的聚合证据并标记覆盖范围。不能为让通用命令运行而把事件数据伪装成 HDD 面板，或读取未获准的标签。允许输入为空时报告缺口，不能伪造零行检查结果。

## 可解释且可复现的处理

只有研究需要且授权范围允许时执行处理；可直接完成常规实现选择，影响标签含义、业务定义或评估口径且无法从上下文确定的决策须澄清。高缺失率可能表示厂商未实现某字段，不自动视为坏数据；同一设备同一时间多条事件也不一定是重复。

处理管线放在 `<项目目录>/data/`：

- `data-contract.yaml`：输入白名单、字段含义、主键、标签/窗口、划分与禁止输入。
- `processing-plan.yaml`：规则、理由、训练拟合范围、输出路径、种子与实现版本。
- `processing-log.jsonl`：步骤、输入/输出行数和哈希、影响数量、理由及实际状态。
- `checkup-before/`、`checkup-after/`：处理前后可比的聚合报告。

原始文件只读；派生数据另存到新的本地目录。只在训练集拟合填补、缩放、特征选择和阈值，复用相同规则处理后续划分。只对获准读取的文件计算哈希，不能递归扫描受保护目录。HDD 共享基准四件套及数据目录禁止修改，研究性变换放在候选或独立派生任务中，并说明与基准的可比性。

没有执行处理时记录 `mode=read_only`、`transformations_applied=[]`；不能写“清洗完成”。缺少能力的检查记录 `not_checked` 及原因，不将它算入通过项。

## 进入实验的证据

明确且可复现的输入/标签语义、训练数据可用、阻断项解决、需决策项有处理或接受理由、评价划分固定、泄漏检查范围与未检查项清楚，随后将数据身份写入项目契约和运行血统。不可检验的核心标签/时间边界阻止受影响实验，但不阻止独立的文献和工程工作。

实验出现异常收益、错例集中或数据漂移时回到这里查证；修改数据身份后建立新 run 和同口径基线，不在原 run 内偷偷替换文件。

方法参考：[伐谋数据分析](https://github.com/baidubce/skills/blob/develop/skills/famou-data-analysis/SKILL.md)。本项目的适配器能力和数据边界优先。
