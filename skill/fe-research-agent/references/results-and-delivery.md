# 效果可视化、证据验收与 Skill 交付

先识别执行路径及本次运行身份，读取真实产物。逐结构调优报告可在搜索完成后单独运行 `fe report <任务目录> --run-id <ID> --workflow` 导出；自动导出由 `workflow.reports.enabled` 控制。报告只读取已存证据，导出失败不改变搜索完成状态。结果图用于解释可观察的效果；变更意图与机制假设须标明是解释，不作为实测结论。

## 选择正确的证据

| 来源 | 读取位置 | 判定边界 |
|---|---|---|
| `fe research` | `<run>/research/report.json`、`lessons.json`、本地节点评估 | `selected` 与 `goal_assessment` 决定联合验收；`highest_score_node_id` 可能违反约束 |
| 历史 HDD Campaign | `<campaign>/results/report.json`、`hyperparameters/ledger.json`、`summary.json`、路线契约及逐 trial 评估 | 区分代码阶段和 HPO 最佳；Campaign 按 ROS 选优不保证其他约束 |
| WebUI 运行回放 | `run_summary.json`、`tree.json`、`events.jsonl`、节点评估 | 展示运行摘要的全局最高分；不能自动当成研究最终可行候选 |
| 宿主项目账本 | `project.yaml`、数据报告、文献、`runs.jsonl`、`decisions.jsonl`、`costs.jsonl` | 补齐前置与跨运行阶段；与 run 汇总去重，未知用量保持未知 |

如果接收到导出的 Skill，只读取实际存在的附件：`references/experiment.json` / `lessons.json` 来自 `fe research`；`references/latest-result.json` / `.md` 来自 Campaign；`references/project/` 属于宿主的全项目总结。按 run/campaign ID、模型、配置、数据和评估器身份核对，不能把文件名中的 latest 或历史分数当成本次结果。附件缺失时标未提供，不补写成绩。

## 图表设计与真实取数

先回答“所选方案改善了什么、是否满足约束、付出多少成本”，再展示搜索过程。使用现有前端、标准绘图库或可离线打开的 HTML；为需要导出分享的科学图提供 SVG/PDF/PNG 和生成脚本。不要执行候选代码来推断图表数据，也不要从源码字面量猜测预测或学习曲线。

| 视图 | 数据与表示 | 关键检查 |
|---|---|---|
| 数据质量 | 字段覆盖、问题分级、处理前后行数 | 说明原始输入或适配器视图，未执行清洗不画成清洗成果 |
| 方案效果 | 原始基线与所选候选的主评分、质量指标、运行成本 | 同任务、评估器、划分与资源；比率与秒分轴，缺失不补零 |
| 研究目标 | 同一候选各约束的目标、实测和通过状态 | 按 `goal_assessment`；不能拼接不同候选的优势 |
| 进化过程 | 实测分数轨迹、岛屿、停滞及失败事件 | 无效节点和未知值保留身份；波动判断沿用后端证据 |
| 参数实验 | 路线内参数/分数分布、trial 状态、默认值与最佳值 | dev 和完整评估分开；不可识别参数说明未调，失败不删除 |
| 成本与效率 | 已计量 Token、评估/fit 数、耗时、首次达标 | 未达标用未达标；缺用量用未知，不用字符数估算账单 |

未保存逐样本预测就不画 PR/ROC 曲线；没有多次复验就不画置信区间；没有过程记录就只展示已保存的最终指标。相关性热图不证明因果。跨任务只展示各自协议和证据矩阵，不平均不同评分公式。

当前 WebUI 的「结果与报告 → 方案效果对比」支持 ROS、已记录质量指标和运行时间切换、来源展开及节点跳转。分项对比要求两次评估有效、评分与摘要一致、划分相同；三岛取最优节点所属岛的唯一初始节点。来源不一致时保留缺口说明。对于 `research.selected` 与全局最优不同或独立 HPO 胜出的情形，宿主另据报告生成最终方案对比，明确候选来源，不冒充已写回原进化树。

## 结论、复验与经验

先报告联合目标结果和停止原因，再给出每条主张的证据：同口径基线、所选候选及哈希、指标、对照、重复次数和局限。单次 val 改进只支持当前验证集，不能宣称独立泛化、跨领域有效或全局最优。复验和消融只在已有授权及项目剩余预算内开展；预算耗尽可交付未达标研究。

使用 [证据索引模板](../assets/evidence-index.template.json)，为每张图和关键结论记录文件、字段/记录定位、实验/候选、划分、哈希、已知限制；未知项保持 null。这里只是宿主管理的交付清单，不是新的评分真源。处理日志、文献来源、节点/TrialLedger、报告应能串联；图表需要保留生成脚本及所需聚合输入。

经验格式沿用研究记录模板：“条件 → 动作 → 证据 → 反例 → 适用边界 → 下一验证”。失败路线也保留，历史最优超参数不能变成跨任务默认值。

## 可分发的统一 Skill

沿用参考 Campaign 的制作方法：通用 `SKILL.md` 保持可复用，本次结果写入 `references/`，完成后打包成根目录为 `fe-research-agent/` 的 ZIP。

1. 将当前统一 Skill 复制到项目的独立交付目录，保留所有本地链接指向的 references、assets 和 UI 元数据；不直接覆盖原源码 Skill 或历史运行。
2. 使用引擎已有导出附件，或在 `references/project/` 加入当前项目报告、证据索引、精简数据质量/处理摘要、文献来源、路线与 HPO 摘要、经验和未完成项。链接与内容都要跟当前身份一致。
3. 在交付副本的 `SKILL.md` 中增加“本项目证据”入口，指向实际存在的 `references/project/报告.md` 和 `evidence-index.json`。目录不完整时标记未提供，不能留下失效链接。
4. 外部大型运行工件用文件清单、候选哈希及明确的本地路径/可访问位置引用；只把获准且必要的聚合证据放进 ZIP。不打包 `.env`、密钥、原始数据、私有集或活动数据库。
5. 校验相对链接不越出 Skill 根目录，读取 ZIP 目录确认只有预期文件；生成 ZIP 的 SHA256 和文件清单。复制归档后核对哈希，保留本地工作目录用于恢复。

仅制作 Skill 时打包通用工作流和模板，不附虚构的项目结果。引擎自动 ZIP 只包含单次运行证据，宿主合并全项目附件后应重新打包，并标明两者范围。Skill 包仍依赖 FaultEvolve 仓库和运行环境，不是独立运行程序。

方法参考：[伐谋结果可视化](https://github.com/baidubce/skills/blob/develop/skills/famou-result-visualization/SKILL.md)，以及本工程参考 Campaign 的“方法与完成结果共同交付”结构。
