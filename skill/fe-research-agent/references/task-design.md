# 算法结构与实验结构搭建

“结构搭建”同时包括方法本身和让方法可比较、可恢复的实验工程。

## 方法设计

将问题拆成输入/标签、预处理、表征或特征、模型/求解器、训练目标、校准或决策、输出与评估。用 `design.md` 说明各模块输入输出、可替换边界和对应假设。选择一个低成本可运行基线，再选择能检验不同假设的路线；不以堆叠模型数代替方法设计。

把结构性修改与数值调优分开：特征窗口集合、模型族、损失定义、集成结构属于路线变化；学习率、叶数、正则化、告警阈值属于固定路线内的参数，但参数可行域仍依赖结构。每条路线保留可复现默认值、条件参数约束、种子和资源限制。

## 工程接入

复用已有可信任务时只建立外部项目配置。新任务在独立目录生成：

- `problem.md`：科研问题、数据及时间/实体划分、评价指标、联合目标、约束。
- `prompt.md`：候选接口、可用依赖、允许的数据、资源及代码约束。
- `init.py`：简单基线；不要把预先调好的最佳解当原始基线。
- `evaluator.py`：可信的本地评价；验证候选输出与数据隔离，返回真实指标。
- `knowledge/` 与项目独立 `evolve.yaml`：前者为证据，后者为引擎配置。

标准四件套通过 `task.adapter: famou` 接入；硬盘使用 `hdd`，内存按实际接口使用 `smartmem`，必要时实现 `module:Class` 适配器。具体方法签名以 `src/faultevolve/tasks/protocol.py` 和当前适配器为准。领域名不是适配器名。

本地结果包含 `validity,combined_score,cost_time,error_info,metric`。主评分为有限、非负且越高越好；损失可在评估协议中预先定义转换，原始值仍保留在 metric。联合目标支持 `combined_score/cost_time/metric.<路径>` 的 `>=` 和 `<=`；不能事后改评分公式掩盖失败。

## 评估器验收

先运行基线，再用已知不同质量的候选检验评分方向；用格式错误/覆盖不全候选检验无效判定。有随机性的任务在相同协议下检查噪声幅度；跨设备/时间任务避免同一实体或未来信息穿透划分。参数与阈值在训练内 dev 上确定，最终 val 按冻结协议比较，私有测试不参与优化。

记录评估器、任务工件、候选及允许访问数据清单的版本/哈希、种子、环境和资源配额。仅对允许的公开输入建立指纹，不遍历或读取私有文件。先通过小样本接口验证，再进入完整数据；两者证据级别分开。

复杂性按任务可测量项目记录：实际模型参数量、树数、文件大小、特征数、峰值内存、训练和推理耗时。`cost_time` 往往包含训练，不能当纯推理时延。若共享评估器不提供某项，在独立诊断工具中测量并关联候选哈希；不能因此改受保护评估器或把估算写成实测。

冻结评价后，宿主可以在预算内修复候选和实现缺陷；如果问题出在可信评估器/数据契约，停止当前比较，修复新任务版本后重跑可比基线，明确前后证据不可混用。
