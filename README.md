# FaultEvolve-ResearchAssistant

**可证伪的故障知识自演化系统 · 可靠性研究助手 Web UI**

> 黑客松主题：基于 Qwen 大模型的科研提效、认知增强与研发范式革新  
> 赛题：A 题「基于大模型 Agent 的器件故障预测算法及自动化调优」  
> 答辩日期：2026-10-06

---

## 一句话定位

**使用场景**：数据中心和硬件厂商的可靠性工程师，需要在不能出域的设备日志（硬盘 SMART、内存 CE/UE 日志等）上持续改进故障预测模型，并弄清楚"为什么会坏"。

**痛点**：大量故障没有明显的 SMART 前兆（约 21% 在经典属性上全为 0），靠调参已经到顶；现有 AI 自演化工具把噪声当成进步，只交付代码和分数，不交付经得起检验的知识；而评估既昂贵又不能把数据交给云端。

**解决方案**：用 Qwen 负责"提出"（特征代码、论断、对手机制、检验方案），用本地数据和预注册的统计检验负责"裁判"，在噪声感知的树搜索里同时优化预测分和证据强度，最终交付更好的预测器、一份分层的知识增量报告，以及可迁移到新设备的 Skill。

## 核心创新点

| 创新点 | 描述 | 借鉴的前人工作 |
|--------|------|---------------|
| **数据裁判锦标赛** | 对手机制两两比赛，每场胜负由一次预先登记、只在确认切片上执行的判别检验决定；Elo 只用于配对调度，最终判定依据累计 e 值和跨环境不变性 | AI co-scientist (Google) 的锦标赛骨架；POPPER (Stanford) 的 e 值序贯证伪 |
| **对手机制 + 跨环境不变性 + e 值证伪** | 每条机制至少配一个非因果对手（混杂、口径、删失）；判别检验覆盖时间先后、剂量–反应、ICP 不变性；证据按 e 值累计，批量判定用 e-BH | POPPER；ICP (Peters 2016)；Platt 强推断 |
| **噪声感知树搜索 + 否证记忆** | 用 bootstrap 标准差设定噪声带 δ，同时约束树的价值回传、洞察提取和反思路由；被否证的假设写入分支记忆 | AutoDiscovery (AllenAI) 的 MCTS + 惊奇；MARS 的对比式记忆；Arbor 的剪枝闸门 |
| **可追溯的知识卡注入 + 校准预筛** | 51 张带来源的知识卡按统计效用检索注入；每个节点记录采纳了哪些卡；Jev 给出校准概率调度评估 | ERA (Google) 的知识注入；FM Agent (伐谋) 的 Skills |
| **分层知识增量报告 + Skill 沉淀 + 跨设备事前预测** | 输出现象 / 机制 / 理论三栏报告；理论层预测写在远期留出和 SmartMem 上，只打开一次 | Theorizer (AllenAI)；AI-Newton；Lakatos 进步纲领 |

## 数据

| 数据集 | 用途 | 说明 |
|--------|------|------|
| **Backblaze Drive Stats (HDD)** | 主战场 | 2013-04-10 至 2026-06-30，7.4 亿盘-天，197 列；2024Q3–2026Q2 约 21% 故障在经典 SMART 全为 0（沉默故障）；位置字段自 2023-07-01 起完整 |
| **SmartMem (Codabench 3586)** | 跨设备泛化 | WWW 2025 内存故障预测竞赛数据；用于 HDD→内存的概念层迁移与事前预测 |
| **Backblaze SSD** | 探索性 | 2025 年起无故障记录，仅作参考 |

## 通用 Skills

系统把调优与发现流程沉淀为符合 SKILL.md 契约的通用 Skills：

| Skill | 触发条件 | 主要步骤 |
|-------|---------|----------|
| 故障预测自动调优 | 新设备或新数据集需要预测器 | 基线评估 → 噪声估计 → 树搜索 → 修复 → 达标停止 |
| 知识发现与证伪 | 需要解释"为什么"或产出结论 | 论断翻译 → 对手机制 → 判别检验 → e-BH 判级 |
| 数据体检 / 沉默故障分析 | 接入新数据时的第一步 | 字段覆盖率、标签语义、删失规则、沉默子集占比 |
| 文献知识卡构建 | 新领域冷启动 | 检索 → 核对来源 → 写卡 → 校验 |
| 实验报告生成 | 运行结束 | 从检验清单自动取数 → 渲染三栏报告 |

**Skills 复用示例**：同一套 Skills 从硬盘数据迁移到内存数据（SmartMem）只需换数据适配器和评分配置。

## 两种隐私部署模式

| 模式 | Qwen 调用 | 数据与评分 | 适用场景 |
|------|----------|-----------|---------|
| **混合云（默认）** | 云端 DashScope（qwen3-coder-plus 生成、qwen3-max 反思） | 始终在本地或用户服务器 | 允许调用外部 API 的环境 |
| **完全本地** | 本地 vLLM/Ollama 部署开源 Qwen3 | 物理隔离 | 军工、金融、运营商等不允许外部 API 的机房 |

两种模式下，**原始数据永不离开本地**，只有白名单聚合量和候选代码跨越数据边界。
