# 统一自主科研 Agent 与执行工具

统一入口是 [`fe-research-agent`](../../skill/fe-research-agent/SKILL.md)：用户给出科研问题，由宿主 AI 按同一 Skill 完成数据理解与处理、文献检索、形成假设、搭建算法和实验结构、配置岛屿、代码进化与超参数搜索，再依据真实评估反馈迭代，交付效果图表、报告与可复用 Skill。

当前版本参考用户指定的 `formal_20261015_194457_qwen38max0902_live/skill/fe-research-agent`，沿用冻结身份、分阶段实评、独立账本和“方法 + 结果附件”打包方式。CLI、科研命令和 Web 共用通过任务适配器评分的逐结构调优核心，数据处理与报告分别可选，见 [统一运行与分层结果](统一运行与分层结果.md)。历史运行的模型、成绩和 NAS 路径不作为新项目默认值。

可向具备本仓库及工具访问能力的宿主提供：

> 使用 `skill/fe-research-agent/SKILL.md`，围绕我的科研问题完成数据检查与处理、文献、方法结构、岛屿配置、算法与超参数迭代，在约定预算内验证目标，输出可追溯的图表、完整证据和方法 Skill。

Skill 已包含项目契约、研究记录、HDD 知识注入/三岛/HPO 配置模板，以及各阶段的决策和验收规则。文献检索、任务搭建、岛屿规划和跨 run 决策由宿主执行；下面的 `fe research` 是单次实验执行入口。Skill 不会作为独立后台进程运行，也不会替代真实数据、可信评估器或任务专用参数接口。

当前 HPO 有两条路径：引擎内 HDD 模板随机搜索，以及统一工作流对演化路线进行的分层参数搜索（复用历史 Campaign 桥接器）。逐结构模式通过当前任务适配器本地评分；其他领域仍需提供有效任务工件与适配器，具体见 [岛屿与参数优化](../../skill/fe-research-agent/references/islands-hpo.md)。仅复制 HDD 配置不构成跨场景泛化。

FaultEvolve 在既有任务适配器和进化引擎上增加 `fe research` 入口。工具自动选择候选、生成代码、执行本地评估、反思并继续迭代，直到同一候选满足预定的全部指标，或预算、停滞等终止条件触发。被调优的是候选算法的特征、模型结构、参数与阈值；不训练大模型本身的权重。

## 快速验证

统一入口按需加载 [数据工作流](../../skill/fe-research-agent/references/data-workflow.md) 和 [结果与交付](../../skill/fe-research-agent/references/results-and-delivery.md)。项目模板同时提供处理日志、阶段状态和证据索引；它们由宿主维护，不能直接作为 CLI 配置。预算和归档目录需从当前项目要求填写。

在仓库根目录使用已有虚拟环境运行：

```bash
.venv/bin/python -m faultevolve.cli research run examples/research/toy \
  --config examples/research/toy/research.yaml \
  --replay-responses examples/research/toy/responses.json \
  --runs-dir /tmp/fe-research-demo --run-id demo

.venv/bin/python -m faultevolve.cli research status /tmp/fe-research-demo/demo
```

该合成示例将阈值候选交给本地评估器，在六个固定样本上实际计算 F1、召回率与误告率。两个候选之后同时达标即停止，不调用 API。候选文本来自离线回放，不能据此宣称大模型自主调优成功或真实故障预测有效。

## 真实任务

已有硬盘基准可以使用独立配置，不修改共享基准四件套：

```bash
# 先在当前终端设置 DASHSCOPE_API_KEY 等必要环境变量。
.venv/bin/python -m faultevolve.cli research run benchmark/hdd_mvp \
  --config examples/research/hdd.yaml --runs-dir .fe/research --run-id hdd-goal-01
```

示例预算为最多 15 轮、100 万 Token、3 小时；目标为 ROS ≥ 35、召回率 ≥ 45%、误告率 ≤ 0.2%、候选运行时间 ≤ 60 秒。它是可编辑的实验起点，不是性能保证。真实运行前确认数据、接口模型与预算均符合当前任务要求。

内存任务复用 `smartmem` 适配器并配置其 dev 评分口径。光放大器或其他任务需要真实数据、可信评估器与适配器；标准四件套可以使用 `famou`。任何领域名称本身都不能替代数据接入和评估实现。详细配置与接入要求见 [科研 Skill 协议](../../skill/fe-research-agent/references/protocol.md)。

## 恢复和停止

前台运行按 Ctrl+C 中断。确认原进程退出后，用原任务、配置和 ID 加 `--resume` 恢复。目标与模型等非预算配置不能悄悄改变；调整 `budget` 可在恢复时生效，并留下人工干预记录。

```bash
.venv/bin/python -m faultevolve.cli research run benchmark/hdd_mvp \
  --config examples/research/hdd.yaml --runs-dir .fe/research \
  --run-id hdd-goal-01 --resume
```

墙钟预算包含中断前耗时与暂停时间，Token 从已存调用账本恢复。预算决定是否继续派发迭代，已发出的调用可能运行到自身超时。SQLite 与控制锁要求本地文件系统；NAS 归档可继续使用旧的 HDD Campaign 流程。

## 结果和规范沉淀

`<运行目录>/research/` 导出：

| 产物 | 内容 |
|---|---|
| `report.json` / `报告.md` | 原始基线、所选候选、逐项目标判定、首次达标轮次/时间、Token、未验证项 |
| `best.py` | 优先选择满足全部约束的候选，按本地评分取最优 |
| `lessons.json` | 候选意图、父节点、真实评分及变化，作用域限于当前任务 |
| `fe-research-agent.zip` | 标准 Skill 与本次报告、经验引用；源码仓库运行时自动生成 |

任务最高评分者可能不满足全部约束，因此报告单独记录 `highest_score_node_id`。模型实际参数量、模型体积、峰值内存必须由评估器返回；缺失时保持未知。Accuracy 与 Precision 分开，自动化覆盖率没有完整步骤分母时不填写比例。

```bash
.venv/bin/python -m faultevolve.cli research compare \
  .fe/research/hdd-goal-01/research/report.json \
  .fe/research/memory-goal-01/research/report.json
```

比较命令提供逐任务证据矩阵，不合并不同评分公式，也不自动证明跨器件泛化。真实效果需要独立时间划分、多随机种子、相同预算对照与必要的迁移消融实验。

## 验证范围

离线测试覆盖目标联合约束、缺失指标与非有限数、基线达标零生成、预算未达标、恢复后成本与原始基线、目标变更拒绝、跨领域合成接口及真实 CLI 回放。合成测试代表工程验证，不能替代内存、硬盘、光放大器真实数据上的完整对照实验。
