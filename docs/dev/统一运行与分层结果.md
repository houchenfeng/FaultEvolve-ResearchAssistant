# 统一运行、数据复检与分层结果

运行分为三个独立部分：核心逐结构调优、可选数据处理、独立报告与展示。`fe run` 开启核心编排；`fe evolve local`、`fe research run` 和 Web 按有效配置的 `workflow.enabled` 进入相同核心。核心通过当前任务的 `TaskAdapter.evaluate` 评分，不限定 HDD。数据处理与报告默认关闭，分别由 `workflow.data.enabled`、`workflow.reports.enabled` 开启。

模型选择与外层预算由实验配置的 `llm`、`budget` 提供，每结构预算由 `workflow.hierarchical` 提供。核心不替换这些值。`examples/experiments/hdd_closed_loop.yaml` 保存 HDD 的 DeepSeek、20 轮、每结构24次试验、启用数据处理和报告的实验设置；共享基准配置保留其原有模型与预算设置。

```mermaid
flowchart LR
    A[任务初始模型与本地评估器] --> B{是否启用数据处理}
    B -->|否：沿用任务输入| E[提出新结构]
    B -->|是：适配器处理并复检| E
    E --> F[仅对该结构分层调优]
    F --> I[选中代码与实测评分写回节点]
    I -->|选择与反思| E
    I -->|停止条件| G[保存最终程序与原始证据]
    G -. 独立执行或显式自动导出 .-> H[只读报告与 Web 展示]
```

## 运行与预算

在仓库根目录执行：

```bash
uv run --no-sync fe run benchmark/hdd_mvp --config-file examples/experiments/hdd_closed_loop.yaml --iterations 10 \
  --env-file .env --runs-dir .fe/runs --run-id hdd-unified-01 --json

# 使用相同任务、配置、本地目录恢复；已完成的参数试验不会重复评估。
uv run --no-sync fe run benchmark/hdd_mvp --config-file examples/experiments/hdd_closed_loop.yaml --resume hdd-unified-01 \
  --env-file .env --runs-dir .fe/runs --json
```

`--iterations 10` 限制代码演化轮数，分层搜索另受以下配置控制：

```yaml
workflow:
  enabled: true
  cpu_limit: 4
  data:
    enabled: false                 # 开启时要求适配器实现数据处理能力
    drop_exact_duplicates: true
    nonfinite_to_missing: true
    accepted_issues: [missing_feature, constant_feature]
  reports:
    enabled: false                 # 可在搜索完成后单独导出
  hierarchical:
    enabled: true
    mode: per_structure
    max_trials: 24
    max_wall_seconds: 43200
```

默认使用 `per_structure`：每个通过静态检查和冒烟的新候选，先在自身参数域中搜索，再把选中的参数版本、对应的实测指标和评分一起写回原节点。结构选择、算子奖励、经验提炼、岛间最优摘要和下一轮生成都使用这个版本。初始 `init.py` 仍按原始参数评估，保留可比较的基线。Jev 预筛不会在调优前跳过结构。

每次新运行从该任务提供的初始模型开始，不预设已有最优方案，不自动导入其他运行的模型或成绩。本次运行内保留已评估的最佳候选，并通过评价反馈持续搜索；`--resume` 仅恢复同一次实验。通用流程可复用到不同任务，具体初始模型、数据与评估器由各任务提供。

`max_trials` 和 `max_wall_seconds` 是**每个候选结构**的预算，包含默认参数评估；例如 20 轮、每结构 24 次，正常候选最多产生 480 次调优试验，另有基线、冒烟和可能的修复候选。修复候选同样先调优再评分。全局演化墙钟预算和已启用的完整评估次数上限也会阻止内层派发。已派发试验按当前任务适配器的评估超时结束，HDD 默认900秒。

搜索复用 `autoresearch-hierarchical-search-cn` 的 Beam 与内层 UCT 风格参数树，固定为当前结构的一条路线，不混入其他岛或模板。没有可识别的显式数值模型参数时，只评估当前代码一次，并在记录中保留空参数域。当前不支持自动提取任意自定义网络配置；可识别范围见 `research_campaign.TUNABLE`。它与 `autotune.hpo.search: random` 是两套不同实现，逐结构模式不应同时启用配额 HPO。

运行结束后只汇总各结构的调优记录，不再追加统一搜索。若确需复现旧流程，可显式设置 `mode: post_evolution`，此时 `max_trials` 是后置搜索阶段的总预算。

`workflow.cpu_limit` 对代码演化中的冒烟、完整验证和后续分层调参统一生效，默认 4 核；实际值还受当前进程可用 CPU 数量限制。执行时同时设置 CPU 亲和性、OpenMP/BLAS 线程数以及已加载的数值库线程池，退出或失败时恢复调用方状态。`runtime-resources.json` 保存请求配额、实际配额与生效线程设置。候选中的 `n_jobs=-1` 因而只使用配额内的 CPU。

逐结构调优在各自的冻结契约内复用已完成试验；只有源码、数据指纹、评估器、评估协议及 CPU 配额一致时才复用成功评分。账本的 `evaluation.evidence` 记录 `cache_hit`、`cache_key` 和命中时的 `cached_from_candidate_id`；逻辑试验仍计入 `max_trials`。失败结果不进入缓存。中断恢复先完成未评分结构的搜索，再允许提出下一个结构；已经完成的试验不重跑。新工作流的后置兼容模式也只调优本次已有候选，不为其他任务补充 HDD 模板；历史 Campaign 保留原冻结路线。无数据副本或数据描述指纹时，不启用成功评分缓存，也不宣称冻结了整个数据集。

SQLite 与处理后的本地数据留在 `--runs-dir`。可用 `--artifacts-dir /mnt/nas/public/users/jiangxiwu/FaultEvolve-huawei/runs` 将公开结果工件写到 NAS；数据库和训练、验证副本不会因此上传到结果目录。Web 的运行根目录须覆盖该工件目录。

已有多指标任务继续使用 `fe research run --config <配置>`，在该配置中启用 `workflow` 即可。科研报告从已完成参数试验的本地评估记录中筛选满足全部目标的方案；最高标量分数与联合可行方案可能不同，两个来源会分别保留。

旧的纯演化实验没有统一工作流合同，不能恢复时直接替换训练口径；用 `fe evolve local ... --no-workflow --resume <旧ID>` 沿原口径恢复，或建立新 ID 运行完整流程。统一工作流当前支持在原本地目录恢复，不支持 `--resume-from` 路径迁移。调优模式变更需新运行；旧正式运行不会转换为逐结构结果。显式增加演化预算时，逐结构模式保留已有结构账本，后置模式归档旧参数结果并重新搜索。

历史 `workflow-input/v1` 运行恢复时继续使用原有冻结数据和评估协议，不根据新增的默认开关重新处理或替换输入；新运行使用分离后的 v2 契约。

## 可选数据处理边界

关闭时直接沿用任务适配器原有的输入与路径，不复制、清洗或体检数据；冻结任务源码并记录适配器和已知数据描述指纹。开启时要求适配器实现 `WorkflowDataProvider.prepare_workflow_data`，返回处理记录、局部环境变量、输入摘要和验证指纹；未实现会在生成模型前明确报错。目前 HDD 实现了这项可选能力，其他适配器可独立接入。

以下规则属于 HDD 适配器的数据处理实现，不是所有任务必须遵循的预处理：

体检读取完整 `train_labels.csv` 和 `train_history.csv.gz`，不再依赖发现适配器先行去重、截断后的视图。自动规则仅删除所有字段完全相同的历史行、把无穷特征值标记为缺失；标签、权重、标识与时间不填补或静默丢弃。缺失和常量是否保留由 `accepted_issues` 明确声明。

冲突标签、冲突的设备日期记录、无法解析的时间或数值、非正或非有限权重、cutoff 之后的历史，以及未解决的需决策问题都会阻断。不会因为退出码为零就把 `review` 当成无质量问题。

处理只写运行目录中的训练副本。验证文件按固定白名单复制，仅供本地评估器使用，不参与预处理统计、规则拟合或模型提示。私有测试集不参与本流程。初始解、所有演化候选和分层候选使用同一训练副本与同一冻结评估器。原始基准四件套及数据不修改；跨运行比较仍需核对数据指纹和处理规则。标签生成过程、跨划分重叠与独立泛化尚未因此得到证明。

## 工件与 Web

| 工件 | 用途 |
|---|---|
| `workflow.json` | 全流程阶段与运行状态 |
| `status.json`、`llm/` | 兼容的阶段状态、流式模型原生进度与 Token 记录（已有显式日志目录则沿用） |
| `data-workflow.json` | 处理规则、影响数量、接受问题、未解决问题、前后数据指纹 |
| `data-checkup/{before,after}/` | 聚合体检报告、字段覆盖和质量依据 |
| 本地 `workflow/manifest.json` | 冻结输入哈希、运行环境版本与配置 |
| 本地 `workflow/processing.py` | 本次处理实现副本 |
| `hyperparameters/{experiment_spec,ledger,summary}.json` | 搜索契约、逐次试验与汇总 |
| `hyperparameters/structures/<node-id>/` | 每个结构的原始提案、搜索契约、试验代码与评分、选中版本；顶层账本为这些记录的汇总 |
| `workflow-result.json`、`workflow-best.py` | 全流程最佳评分、来源与最终程序 |
| `reports/完整运行报告.md/html`、`effect-report.json` | 独立报告步骤生成的展示工件 |
| `report-status.json` | 报告导出状态，与搜索完成状态分开 |

Web 结果页通过 `/api/runs/{run_id}/workflow` 展示数据处理与复检、路线默认/最佳评分、实测评分曲线、路线筛选、父候选、参数变化、耗时、调度奖励和晋升决策，并提供最终程序下载。失败或未记录的评分保持未知；请求失败、记录损坏和记录缺失分别展示。后台只投影聚合字段，不提供训练/验证副本、原始参数账本中的本机路径或评估证据文件下载。

## 独立报告与各阶段 Skill 交付

核心完成时只保证原始证据、`workflow-result.json` 与 `workflow-best.py` 已保存。报告不参与评分和父节点选择。关闭自动导出时可以运行：

```bash
fe report <任务目录> --run-id <运行ID> --workflow \
  --runs-dir <本地运行根目录> --artifacts-dir <产物根目录> --json
```

导出过程只读数据库与参数账本，不训练模型、不调用 LLM，也不更新节点成绩。`workflow.reports.enabled: true` 仅表示搜索完成后自动调用同一报告模块；报告失败写入 `report-status.json`，不把已完成搜索改成失败。报告开关不属于搜索输入契约，允许完成后调整或独立重建。Web 读取这些结果工件；没有导出的报告明确显示未记录。


`scripts/export_closed_loop_delivery.py` 从本地 SQLite 和逐结构参数账本导出报告，不触发评估器或模型调用：

```bash
python scripts/export_closed_loop_delivery.py --run-id <运行ID> \
  --runs-dir <本地运行根目录> --artifacts-dir <产物根目录>
```

运行中增加 `--partial`，只输出已完成记录；完整 Skill 必须在工作流完成后生成。

- `reports/stage-metrics.csv/json`：基线、各轮结构默认参数与调优后版本，以及修复候选的实测预测指标、参数静态估计、源码复杂度、运行时间与逐轮 Token。
- `reports/parameter-trials.csv/json`：各轮全部内层试验、父试验、参数配置及指标；参数搜索不消耗 LLM Token。
- `reports/token-ledger.csv`：提供商每次调用的用量与归属；缓存命中不计新增用量，未知用量保持未知。
- `reports/convergence.csv`、`完整运行报告.md/html`：收敛轨迹、配对调优增益和本次观察的证据范围；HTML 可按阶段、岛和节点筛选。
- `skill/fe-closed-loop-tuning/` 和 `fe-closed-loop-tuning.zip`：包含本次报告与结构化证据的标准化 Skill。

补充的准确率、TP/FP/FN/TN 在本地评估器加载层从同一份预测与标签计算，不改共享 `evaluator.py`、评分公式或原指标。准确率采用机队权重，另报无权样本准确率；误告和漏告数量为加权数，可能是小数。参数量为源码配置下的容量估计，支持展开显式参数字典；未知值留空，不把静态估计称为训练后实测。FLOPs、模型文件大小和真实内存没有测量时不补造。

逐轮 Token 按上轮完成至本轮完成的时间窗口统计，包含生成、反思和修复；不按生成调用里的父节点 ID 误归属到父轮次。报告另列尚未归入已完成轮次的调用，使逐阶段分配可以与提供商总账核对。内层搜索只有本地评估消耗，不能用零 Token 表示零算力成本。

结果页也能读取历史 HDD Campaign 的 `hyperparameters` 和 `results/report.json`，历史未执行的数据处理不会补记为已执行。进程在调参阶段退出时不会仅因代码演化摘要存在而被标为全流程完成。
