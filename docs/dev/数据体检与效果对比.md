# 数据体检与方案效果对比

这次改进参考百度伐谋的 [famou-data-analysis](https://github.com/baidubce/skills/blob/develop/skills/famou-data-analysis/SKILL.md) 和 [famou-result-visualization](https://github.com/baidubce/skills/blob/develop/skills/famou-result-visualization/SKILL.md)（2026-10-16 查阅的 develop 版本），采用数据理解、质量分级、处理理由和效果主图的组织方式。代码使用 FaultEvolve 的适配器、CLI、API 和 React 组件独立实现。

## 数据理解与处理建议

在仓库根目录运行：

```bash
fe data checkup benchmark/hdd_mvp --out build/data-checkup
fe data checkup benchmark/hdd_mvp --strict --json --out build/data-checkup
```

默认显示中文报告；`--json` 返回机器可读摘要。输入来自适配器的 `discovery_frames`，只检查训练视图。输出目录不能位于该任务的 `data/` 内。

| 产物 | 内容 |
| --- | --- |
| `data_facts.json` | 标签行数、正负例数、历史行数、字段、质量状态 |
| `data_quality.json` | 问题分级、聚合计数、字段依据、处理建议、视图指纹、检查限制 |
| `data_report.md` | 数据概况、质量问题、处理建议与可复现依据 |
| `field_coverage.csv` | 非空率、缺失数、非有限值数、不同值数量；UTF-8 BOM |
| `silent_subset_stats.csv` | 保留适配器的可选扩展；未实现时只写表头 |

检查覆盖必需字段、空表、缺失标识/时间/标签、无效二分类标签、单类别、标签设备重复、设备与时间组合重复、标签与历史关联缺口、时间可解析性、特征缺失/无穷值/常量。

`ok=true` 仅表示报告生成成功。`quality_status` 为：

- `blocked`：存在阻断问题，应先修复数据契约或记录缺口。
- `review`：需依据业务含义复核，例如 SMART 字段高缺失率可能来自厂商差异。
- `ready`：当前已执行的检查未发现问题。

普通模式生成报告后退出 0；`--strict` 在存在阻断问题时先保存报告，再退出 2。读取或处理失败退出 1。这样交互分析可查看全部证据，自动流程可按退出码阻止继续。

报告中的建议不自动执行。处理时保留原始文件，单独保存转换脚本、配置及各步骤影响行数；填补、归一化和特征选择只在训练数据拟合。

### 检查范围

HDD 适配器在返回训练视图前已经去重标签、过滤 cutoff 之后的历史并转换数值类型。报告因此不能证明原始文件没有重复、解析异常或未来信息泄漏。跨划分重叠、逐设备 cutoff、标签生成和统计功效需要另外验证。本命令不读取验证标签或私有测试集。

旧版本把 `min_detectable_effect` 固定为 0.05；现在保留该字段但返回 null，并注明未做功效分析，避免下游把常量误认为实测结果。

指纹覆盖当前训练视图的列名、类型和有序行值，不包含 DataFrame 索引；同时记录 pandas 版本。指纹可用于核对同环境下的输入视图，不等同于原始文件哈希。

## 方案效果可视化

打开 WebUI 的运行详情 →「结果与报告」，首屏新增「方案效果对比」：

- 默认展示运行摘要中的初始和最佳 ROS，共用从零开始的刻度。
- 下拉框切换已记录的 F1、稳健 F1、AUPRC、召回率、误告率、漏告率与运行时间。比率转为百分数展示，时间单独使用秒。
- 右侧显示最优节点的变更意图，并提供初始/最优方案的进化树入口。
- 展开「查看指标来源」可核对指标字段和节点 ID。

分项对比要求：初始节点可唯一确定、两次评估均有效、节点评分与运行摘要一致、评估划分已记录且相同。三岛运行使用最优节点所在岛的唯一初始节点。存在歧义或记录不全时，保留摘要分数图并解释分项对比不可用的原因；读取失败可重试。

未知值不补零，非有限数值或超出 [0,1] 的比例不绘制，未记录的指标不虚构。柱长仅表示测量值，不替代已有的波动带判断；变更意图不作为效果证明。未保存预测序列或训练曲线时不生成这些图。
