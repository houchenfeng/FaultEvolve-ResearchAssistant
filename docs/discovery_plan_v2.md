## 1. 核心主张（一段话）

FaultEvolve 要交付的不是一个更高的分数，而是一份**分三层、每层都可以被否证的知识增量**：
- **现象层**：新的预测因子或因子组合，要在置信区间、时间留出、FDR 控制和阴性 / 阳性对照下保持稳定，而且相对 51 张知识卡是新的；
- **机理层**：说明这个因子为什么、经过哪条路径导致故障。判定依据是跨环境不变（数据中心、vault、型号、季度），以及在“对手机制也能解释”的地方仍然胜出；
- **原理层**：一条更一般的理论，既能解释已有现象，又能**事先写下**对没见过的设备或时期的预测，再在这些数据上检验（Backblaze 的 2025Q2–2026Q2 远期留出，以及 SmartMem 内存；HDD→SSD 因 SSD 故障记录不足只作探索性参考）。

实现上，我们直接借用 AI co-scientist 的“生成 → 两两对决 → Elo → 进化 + 元评审”锦标赛、POPPER 的 e 值序贯证伪、AutoDiscovery 的 MCTS + 贝叶斯惊奇，并把它们放进 FaultEvolve 已有的噪声感知树搜索和否证记忆里。我们主要的改进是**数据裁判锦标赛**：对手机制之间的每一场比赛，由一次预先登记的判别性数据检验决定胜负，而不是由 LLM 裁判；Elo 按检验结果更新，最终判定则依据有错误控制的累计 e 值。Backblaze 现在提供 2013-04-10 至 2026-06-30 的逐盘逐日数据（公开 Iceberg 表，744,525,690 行、197 列【已核实 2026-09-28】），这让“长轨迹、远期留出”可以同时做；同一数据集内的 HDD→SSD 跨设备检验则因 SSD 故障记录不足（2025 年起为 0）而偏弱，跨设备泛化改由 SmartMem 内存数据承担。我们不宣称首创，只宣称这个组合在可靠性领域落地，并且每一层都有对照和否证证书。

## 2. 三层定义表

| 层级 | 什么算数 | 内在逻辑 | 验证方式 | 产出物 | 强度分级 |
|---|---|---|---|---|---|
| **现象层**（新特征因子） | 一个可以写成代码的预测变量或变量组合 X，加上一条论断 C = ⟨条件 S、X、结果 Y、方向与量级 θ（附 CI）、适用范围 R⟩，并写明否证条件。仅仅“分数涨了”不算 | **稳定**：换切分、换时间、校正了整个搜索的多重比较之后，效应仍然存在；而且知识卡推不出它 | ① 按盘 bootstrap 的效应量 CI；② 时间留出（远期 2025Q2–2026Q2）方向一致；③ 对全部送检论断做 BH / e-BH 的 FDR 控制；④ 打乱标签阴性对照（期望通过数为 0）；⑤ 植入信号阳性对照（分 3 档强度，画检出功效曲线）；⑥ 相对 51 张卡的新颖性：语义上由 Qwen 盲推、Jev 逐卡判断蕴含，功能上看在 F(K0) 之上是否仍有增量，且 max\|ρ\|、R² 低于阈值 | **现象卡**：陈述、效应量与 CI、分层森林图、新颖性证据、血统（节点 → 卡片 → DOI） | 确认（已知规律，在本数据上被实证）/ 修正（已知规律失效，或只在更窄范围成立）/ **发现**（K0 推不出，且全部检验通过）/ 已否证（负知识） |
| **机理层**（因果路径） | 一张结构化因果图 M（节点可以是 SMART 列、潜变量、环境变量、故障；边标出符号、滞后和形状），**至少配一个对手机制**，其中至少一个是非因果解释（混杂、厂商计数口径、运维更换造成的删失） | **不变 + 判别**：真正的机制，其条件关系在环境变化时保持不变（ICP）；而且在对手机制给出不同预测的地方，它的预测通过、对手的预测失败（Platt 强推断） | ① ICP 跨环境不变性，环境取数据中心 / vault（2023-07-01 起才完整，2023Q3 以后可用【已核实 2026-09-28】）、型号、季度；② 对手判别检验（数据裁判锦标赛，§4）；③ 时间先后；④ 中介；⑤ 剂量–反应；⑥ 条件异质性与聚集。每项检验的 p 值都转成 e 值，累计判定 | **机制卡**：主机制和对手的因果图、每场比赛的检验与 e 值、Elo 和可信度轨迹、不变性结果、**否证证书**（哪个检验、哪个环境、哪段数据、e 值多少、对应哪个预注册哈希） | L1 关联 → **L1+ 机制佐证**（这是观测数据能达到的上限）；达不到 Pearl 的 L2 干预。判定结果为：成立（佐证）/ 未定（功效不足）/ 已否证 |
| **原理层**（新理论） | 一张理论卡 = 少数几个概念 + 一条定律 + 适用范围 + **至少一条事先登记的新预测**。只做事后解释的不算 | **统一 + 新预测**：用更少的概念解释多个机制或现象（MDL / 解释一致性），并**在还没看数据之前**说出下一个现象（Lakatos 意义上的进步纲领） | ① 预测在预注册之后，写在从没用过的设备或时期上：2025Q2–2026Q2 远期留出、SmartMem；HDD→SSD 只作探索性参考；② 统一性：联合描述长度（BIC / MDL 近似）比各现象分别建模的总和更短；③ 与工程公理相容（计数单调、风险非负、屏蔽资源有限）；④ 统计纲领的进步性：被证实的新预测数，对比事后补丁数 | **理论卡**：概念、定律、范围、预测登记表（哈希 + 时间戳）、每条预测的检验结果、MDL 比较、补丁记录 | 候选理论 → **进步纲领候选**（至少一条事前预测在未见数据上被证实，且没有被否证）→ 退化（主要靠事后补丁维持）。**不宣称普适定律** |

三层是逐级依赖的：现象卡是机制的输入，至少两条已经成立、而且共享结构的机制，才触发理论层。每一层失败了都写入负知识，不会被丢掉。

## 3. 自演化树搜索怎样实现三层

### 3.1 节点类型

| 节点 | 层级 | 内容 | 现状 |
|---|---|---|---|
| `Program`（特征程序） | 现象层 | 候选代码，只允许修改 `make_features` 这个 EVOLVE 块 | 已有（UCT + 渐进加宽 + 子树 max 回传 + 噪声 δ） |
| `Claim`（论断 / 现象卡） | 现象层 | 论断 JSON：S、X 代码、Y、θ、R、否证条件、最近的卡片 | 新增 |
| `Mechanism` | 机理层 | 因果图 JSON，列出对手 id、预测和先验 | 新增 |
| `Test` | 机理层 / 原理层 | 编译好的检验程序：类型、参数、数据切片、各机制在这项检验上的预测符号 | 新增 |
| `Theory` | 原理层 | 概念 + 定律 + 范围 + 预测登记 | 新增，只有当至少 2 条成立机制共享结构时才触发 |

### 3.2 算子

| 算子 | 输入 → 输出 | 来源或依据 |
|---|---|---|
| `refine` / `inject` / `discover` | 父程序 + 卡片 + 分支记忆 → 新程序（`discover` 同时输出一份 `<claim>` 草稿） | 已有 refine；inject / discover 属于 v1 规划 |
| `translate_claim` | 特征代码 + 聚合统计 → Claim | v1 流水线第 ② 步 |
| `propose_rivals` | Claim → 至少 2 个 Mechanism（其中至少 1 个是非因果解释） | co-scientist 生成、Platt |
| `derive_tests`（判别预测编译器） | 一对机制 → 只保留两者预测方向不同的 Test，按期望信息增益排序 | POPPER、Piriyakulkij（EIG） |
| `explain_anomaly` | 惊奇（漏报子群、与知识卡矛盾、信念方向翻转）→ 新 Claim | KEKADA、AutoDiscovery |
| `revise_mechanism` | 输掉比赛的机制 → 加上条件的修正版（新节点，必须在没用过的数据上检验，并计为一次补丁） | co-scientist 进化；Lakatos 补丁计数 |
| `unify` | 至少 2 条成立机制 → Theory | AI-Newton（概念 → 推广）、MDL |
| `predict_new` | Theory → 写到未见设备或时期上的预测，**先登记哈希再检验** | Lakatos、Theorizer 的回测 |

### 3.3 价值函数（选择用，不用于报告）

```
V(node) = ROS 提升（超过噪声 δ 的部分，现有实现）
        + λ1 · log E（机制累计 e 值，只在确认切片上计算）
        + λ2 · 贝叶斯惊奇（只算方向翻转，即信念跨过 0.5）
        + λ3 · 通过不变性检验的环境数
        （λ 属于【设计选择】；报告分仍然只取真实 ROS 和预注册的检验结果）
```
关于 AutoDiscovery：它的惊奇来自 LLM 对后验信念的采样。我们的惊奇改为由**检验统计量驱动的可信度账本**来计算，LLM 采样只用来给先验。

### 3.4 分支记忆 + 否证证书

现有通路：`engine._reflect_hypothesis_refuted` → `tree.add_refuted_hypothesis` → `branch_memory.refuted_hypotheses` → `operators.refuted_hypotheses_section` 注入下一轮提示。我们把原来的一句话记录升级为结构化的**否证证书**：

```
{mechanism_id, 对手id, test_id, test_type, 环境/切片, 统计量与CI, e值, 预注册哈希, 日期}
```
- 被否证的机制前缀加 `[MECH]`，同时进入跨分支负经验（`get_foreign_insights` 的 negative 部分），避免其他分支重复尝试；
- 被佐证的机制写入 `branch_memory.summary`，并作为高先验“发现卡”广播给所有分支（沿用 01 设计文档 §5.3 的通路）；
- 证书还会供理论层使用：如果多个机制在同一类检验、同一个环境上一起失败，这本身就是一个需要统一解释的现象。

### 3.5 第 4 层反思：机制层

- 现状：`src/faultevolve/cloud/insights.py` 里 `LayeredReflector` 的 `LAYERED_REFLECTION_PROMPT`，`layer` 只取 `implementation | design | hypothesis` 三个值；`engine.py` 的 `_apply_reflection` 按 Δ 与 δ 的关系，分别路由到 `_reflect_design_issue`、`_reflect_hypothesis_refuted` 和 `_reflect_positive`。
- 新增 `mechanism` 层，触发条件：(a) 有论断通过了搜索集检验；或 (b) 同一机制下有 2 条论断在确认切片上失败。触发后调用 `MECHANISM_REFLECTION_PROMPT`，输出因果图 JSON 和对手机制，然后交给本地检验执行器；结果分三路：否证、佐证、未定（未定会生成“下一步最该做的检验”）。
- 反向指导搜索：机制摘要通过新增的 `OperatorContext.set_mechanism_context` 进入 refine / discover 的提示。例如“读头 / 伺服机制”被佐证后，就引导搜索去 1/3/7/10/191–193 这些属性里找沉默故障的前兆。
- 设计层同时升级为 CriticAL 式的**显著批判**：输入不再只是 Δ 和代码 diff，还要带上前 k 个显著差异子群及其 p 值 / e 值（T10）。

## 4. 数据裁判锦标赛（核心改进）

### 4.1 与 co-scientist 的关系
AI co-scientist 的流程是：生成 → 反思 → 排名（两两辩论的锦标赛，Elo 初始值 1200）→ 进化 → 邻近 → 元评审。根据其论文描述，排名主要由 LLM 模拟的科学辩论决定，真实验证放在事后的湿实验中完成。我们**保留**整个锦标赛骨架（种群、两两对决、Elo、进化、元评审），**替换**比赛的裁判：每一场比赛的胜负由一次数据检验决定。这样做的理由有文献支持：LLM 擅长给出结构和符号，但判断不准效应大小，也不擅长应用规则（Kıcıman 2023、Automated Social Science、Hypothesis Search、Phenomenal-yet-Puzzling）。

### 4.2 比赛流程

```
① 参赛池：每个现象簇 = Qwen 生成的机制 {M1..Mk}
          + 固定的非因果对手 {M_confound(型号/部署批次), M_artifact(厂商计数口径), M_censor(Backblaze 按 187>0 更换造成的删失)}
          + 兜底类 M_other
② 配对：瑞士制，优先配 Elo 接近、判别检验期望信息增益大的两个机制
③ 编译：derive_tests(Mi, Mj) → 只留下两者预测符号相反（+/−）或一方预测为 0 的检验
        Jev（或先用 Qwen 占位）做判别性 / 相关性检查：P(两者预测确实不同)，低于阈值就丢弃（POPPER 消融显示这一步能压住 I 类错误）
④ 登记：预测矩阵（机制 × 检验 → 符号）+ 检验参数 → sha256 → 提交
⑤ 比赛：本地执行器只在【确认切片】上运行；设计智能体只能看到表结构（这是 POPPER 有效性的前提）
⑥ 判定：检验结果换算成 e 值
        e ≥ 阈值且方向符合 Mi → Mi 胜；符合 Mj → Mj 胜
        两边都不够强 → 平局，标为“功效不足”，同时报告最小可检测效应，不判否证
⑦ 更新：Elo：R_i ← R_i + K·(S − E_i)，E_i = 1/(1+10^((R_j−R_i)/400))，K 按证据强度加权，K = K0·min(1, |log e| / log(1/α))【设计选择】
        可信度账本：log-odds 加上被截断的 log BF（单次截断在 [1/10, 10]，沿用 v1）
        机制累计 E = ∏e_i
⑧ 进化：输家交给 revise_mechanism（加条件、缩小范围，计一次补丁）；赢家交给 derive_tests 继续找新的判别点
⑨ 元评审：汇总全部否证证书，找出哪类检验最有判别力、哪个环境最容易打破不变性、哪些机制在同一处一起失败
          → 写入生成提示，并作为 unify 的种子
```

### 4.3 为什么 Elo 只用来排序，判定用 e 值
Elo 假设各场比赛相互独立，但同一数据上的检验彼此相关，所以 Elo 只用于**配对调度和演示**。机制最终是否“成立”，由三条规则决定：
- 机制成立 = 在判别检验上累计 E ≥ 1/α，**并且**通过 ICP 不变性检验，**并且**在多个机制之间做 e-BH 之后仍然入选；
- 已否证 = 自己登记的判别预测被显著违反，并生成否证证书；
- 其余一律判为未定。

### 4.4 数据预算纪律
- 每个确认切片上的每项检验，只对同一个比赛族使用一次。修正版机制**必须**在还没用过的切片上比赛：下一个季度、另一批留出盘，或者远期留出集。如果没有这样的数据，就标为“待检验”。
- 远期留出集（2025Q2–2026Q2）不参与锦标赛，只留给原理层的事前预测，**只打开一次**。

### 4.5 锦标赛自身的检验（这是答辩时可以宣称的实验）
1. **植入机制对照**：在半合成面板中注入一条已知路径（已知滞后、跨环境不变），再加一条只在某个环境里成立的伪关系。期望锦标赛把真路径排第一，并用 ICP 拒绝伪关系。
2. **LLM 裁判 vs 数据裁判**：对同一个参赛池，分别用 LLM 两两辩论（co-scientist 式）和数据裁判各跑一遍排名，然后用**远期留出集上预先登记的检验结果**当“真值”，比较两种排名的一致性（例如 Kendall τ，以及冠军机制的预测命中率）。**结果未知**，无论哪边赢都如实报告。
3. **打乱环境标签**：打乱环境标签后，不变性检验不应该给出系统性的通过或拒绝。

### 5.2 现象层实验 E1：特征发现
- **设置**：冻结 LightGBM 的超参数、按盘分组 5 折 OOF、阈值规则和切分，只演化 `make_features`。有两种配置：发现模式（`base=k0`，F(K0) 全部放进模型）和重新发现模式（`base=none`，关闭卡片，作为阳性对照）。新数据让窗口不再局限于 14 天：全部年份 33,331 块故障 HDD 的历史跨度中位数 1,032 天（p10 184、p90 2,375 天；3,018 块在 2013-04-10 左删失）【已核实 2026-09-28】，可以用 30 / 90 天和整个寿命期的轨迹特征（窗口长度属于【设计选择】）。
- **重点子集**：沉默故障 S0（5/187/197/198 全为 0 或未上报），以及严格版 S0-strict。实测（HDD，2024Q3–2026Q2）：故障当天 5/187/197/198 原始值全为 0 或 NULL 的占 21.2%（1,973 / 9,316；含 19 次 SSD 故障时为 1,990 / 9,335 = 21.3%），30 天窗口 20.1%，季度间 14.4%（2025Q1）–32.0%（2025Q3）【已核实 2026-09-28】；口径无法区分“未上报”和“真实为 0”。各切分的正样本数和厂商分布仍需计算。
- **对照**：打乱标签（在型号 × 厂商层内置换）；3 列噪声探针；植入信号（分 3 档）；关闭卡片后重新发现 FE01/FE03。
- **指标**：效应量与 CI；远期方向一致率；BH / e-BH 之后的通过数；新颖性（语义 + 功能）；S-Recall@FAR0.2%、S-AUPRC；**每 100 次评估的已验证新颖发现数（VND/100）**；成本（token、CPU 小时、墙钟时间）。

### 5.3 机理层实验 E2：不变性 + 锦标赛
- **环境**：数据中心（6 个：phx1、sac0、sac2、iad1、ams5、yyz1）、集群（每季 6–7 个）、vault（每季 207–259 个；pod_id 是 vault 内编号，只有 20 个取值），均只在 2023Q3 以后可用【已核实 2026-09-28】；另有型号、季度，以及盘龄段。正样本少的环境要合并，最小正样本数属于【设计选择】。
- **检验族**：ICP（分环境的风险模型，用环境 × 因子交互项或 Cochran Q 检验）；时间先后（配对首次发生日期，以及“滞后 vs 超前”回归）；剂量–反应（Cochran–Armitage、保序回归加置换检验）；条件异质性；聚集（在型号和盘龄层内置换 vault / pod 标签）；中介（Stretch，Imai 框架，写明序列可忽略性假设）。长轨迹让时间先后和剂量–反应检验在功效上变得可行。
- **必配的对手**：M_censor。Backblaze 在 187>0 时就安排更换，所以“187 → 故障”的关联有一部分是运维规则制造出来的。
- **对照**：植入机制和植入伪关系（§4.5）；打乱环境标签。
- **指标**：各机制的累计 E、ICP 接受的因子集合、Elo 和可信度轨迹、否证证书数、未定比例及其最小可检测效应、LLM 裁判与数据裁判的一致性。

### 5.4 原理层实验 E3：事前预测
- **触发**：至少 2 条成立机制共享结构。示例候选原理（**纯属假设**）：“风险由屏蔽资源的消耗速率决定，而不是由损伤存量决定”。在 HDD 上对应重映射消耗备用扇区，在 SSD 上对应备用块 / 磨损，在 DRAM 上对应 CE 累积吃掉 ECC 余量。
- **事前登记**（PREREG v2，打开数据之前写）：
  - P-时间：在 2025Q2–2026Q2 上，某个机制的效应方向、量级区间和适用范围；
  - P-内存（跨设备主预测）：SmartMem 上 CE 增长率优于 CE 累计数；
  - P-设备（探索）：Backblaze SSD 上“消耗速率类特征优于存量类特征”。SSD 全部年份只有约 235 次故障、2025 年起为 0【已核实 2026-09-28】，功效弱，只作探索性检查，不计入事前预测命中率；
- **判定**：预测只检验一次，报告命中与否以及 CI；统一性看联合 MDL / BIC 是否短于各现象分别建模的总和；与工程公理做约束检查；统计补丁数与被证实预测数之比。
- **对照**：再登记一条“对手理论”（例如“风险由存量决定”）的相反预测，两者在同一数据上比赛，作为原理层的锦标赛。
- **阳性对照（Stretch）**：电池 Severson 数据（CC BY 4.0 镜像），检验能否重新发现 ΔQ 方差特征。充电策略是人为设定的，这是全方案唯一接近干预证据的地方；但要注意 Qwen 可能只是“回忆”出了这个特征。

## 6. 先例：借鉴什么，改进什么

| 先例 | 借鉴 | 我们的改进（不宣称首创） |
|---|---|---|
| **AI co-scientist**（Google，arXiv 2502.18864；Nature 2026） | 生成 → 两两对决 → Elo → 进化 → 元评审的锦标赛骨架；多假设并存 | **数据裁判**：每场比赛都是一次预先登记的判别检验；Elo 按检验结果更新；最终判定用 e 值 + 不变性；元评审汇总的是否证证书，而不是评审意见 |
| **POPPER**（Stanford，arXiv 2502.09858） | p→e 校准、e 值累乘、E ≥ 1/α 时拒绝；相关性检查器；设计智能体只看表结构 | 从“单个 H 对 H₀”扩展到**对手机制之间的判别**；加入 ICP 跨环境不变性；多机制之间用 e-BH（POPPER 在局限性部分也建议这样做）；相关性检查交给 Jev，并用 Brier 记账 |
| **AutoDiscovery**（AllenAI，arXiv 2507.00310） | MCTS + 渐进加宽；贝叶斯惊奇只在方向翻转时计数；假设去重 | 惊奇改由检验统计量驱动的可信度账本计算；价值函数同时包含预测分（ROS，受噪声 δ 约束）和认识论分；惊奇节点接到 KEKADA 式的“划界 → 机制”流程 |
| Kosmos | 共享世界模型；每条论断都能追溯 | 世界模型 = 机制账本 + 证书库；报告中的数字全部从检验 manifest 自动读取 |
| ICP / 序列 ICP（Peters 2016；Pfister） | 机制 = 跨环境不变的条件分布 | 把 Backblaze 2023 年起的位置字段当作环境；作为机制晋升的必要条件 |
| KEKADA、BACON | 惊奇驱动的发现；用“重新发现”验证系统 | 沉默故障子群作为惊奇靶子；关闭卡片后重新发现 FE01/FE03 |
| SAGE、Arbor、MARS | 多假设失败归因、held-out 合并闸门、跨分支记忆 | 否证证书结构化，并且可以跨分支检索；噪声 δ 贯穿价值回传 |
| AI-Newton、Theorizer、Lakatos | 概念 → 推广；用未来数据回测；进步 vs 退化 | 事前登记的预测写到远期留出和 SmartMem 上（SSD 仅探索）；统计补丁数 |
| FM Agent（伐谋） | 固定下游模型只演化特征（AmEx 案例）；云生成 + 本地评估 | 本地回传的是结构化证据（效应量、CI、e 值、证书），不只是一个标量分数 |

一句话表述：**我们站在 co-scientist、POPPER 和 AutoDiscovery 的肩上，把 LLM 裁判换成数据裁判，把单假设证伪升级为对手机制判别加跨环境不变性，并在同一棵树里同时优化预测分和认识论分。**

## 9. 60–90 秒演示与兜底

### 9.1 脚本（约 85 秒）
1. **（10 秒）痛点**：“FAST'07 显示，超过 36% 的坏盘 SMART 计数全为 0。调参已经到顶，缺的是新知识。”屏幕显示我们数据中 S0 的实际占比：2024Q3–2026Q2 的 HDD 故障中约 21% 在经典 SMART 属性上全为 0 或未上报。
2. **（15 秒）现象层**：左边是演化出的一段特征代码，右边是论断卡：条件、效应和 CI、范围、否证条件，以及“相对 51 张卡是新的”的证据。
3. **（30 秒）机理层：数据裁判锦标赛**：屏幕上是对阵图，主机制 vs 对手（包括“运维删失”和“混杂”）。每一场比赛亮出一次检验（时间先后 / 剂量 / 跨数据中心不变）及其 e 值，Elo 条随之变化；输家变灰，带着否证证书掉进分支记忆。一句话点题：“co-scientist 用 LLM 当裁判，我们让数据当裁判。”
4. **（15 秒）原理层**：理论卡加上预测登记的哈希和时间戳 → 打开 2025Q2–2026Q2（或 SmartMem）→ 命中 / 未命中。
5. **（15 秒）可信度**：打乱标签后通过数为 0（如果确实如此）；植入信号的检出曲线；知识增量报告三栏；云端负责想，本地负责验。

### 9.2 兜底
- **没有达到“发现”级**：如实说“在预注册检验下，本轮没有达到发现级的论断”，然后展示：修正或否证级的结论（例如某张卡在沉默子集或某个数据中心不成立）、被否证机制的证书、阳性对照找回了植入信号 / 植入机制、阴性对照为 0。主张：“这是一台经过校准的发现机器：能找回已知规律，不编造不存在的规律，而且能把失败变成证书。”
- **事前预测没有命中**：这本身就是一次诚实的否证，在 Lakatos 意义上照实展示。
- **运行没跑完**：用录屏 + 离线脚本，对 hdd_mvp 已有的基线和 FE01/FE03 已知论断跑一遍“论断 → 锦标赛 → 证书”，并明确标为“流程演示”。

## 10. 风险与诚实声明

1. **新颖性只能宣称 P 新颖**：“相对系统先验 K0（51 张卡 + Qwen 背景知识）是新的”可以自动检验；H 新颖需要穷尽文献，8 天内只能说“检索未见，属于 H 新颖候选，待专家复核”。**不说**“AI 发现了人类不知道的硬盘规律”。
2. **观测数据只能给出佐证**：机理层的上限是 L1+（Hill 视角 + 不变性 + 判别检验）。ICP 的保证依赖“环境只通过原因变量影响故障”等假设，而型号既可能是环境，也可能是原因。未测混杂始终存在：数据**没有固件、生产批次、SMR/CMR、工作负载字段**，批次机制只能靠部署时间或 vault 来代理。
3. **标签语义**：Backblaze 的 failure 表示“盘被标记更换”，不等于物理失效；187>0 就更换的规则会造成删失，所以 M_censor 是必配对手。
4. **公开数据的“留出”靠纪律**：远期留出集和 SmartMem 是否只打开一次，依赖预注册哈希和提交时间戳。Qwen 可能在预训练中见过 Backblaze 对 2025 年的总结，所以理论预测要记录生成时 Qwen 引用了什么依据。
5. **功效不足**：S0 和部分环境的正样本可能很少，负结果要判为“未定”而不是“否证”，并报告最小可检测效应。
6. **锦标赛的局限**：检验之间相关，所以 Elo 只用于调度；关键实验在逻辑上并不决定性（Quine–Duhem），所以我们保留兜底类和“未定”；LLM 检查器会高估相关性（POPPER 报告检查器判定 85%、人工判定 77%），要做随机人工抽检。
7. **SSD / 内存字段与 HDD 不同，且 SSD 故障记录不足**：跨设备预测只能写在**概念层**（例如“消耗速率 vs 存量”），需要人工确认映射关系；Backblaze SSD 2025 年起没有故障记录，HDD→SSD 只作探索，跨设备泛化以 SmartMem 为主。
8. **时间**：主线引擎的改动可能来不及合并，MVP 已设计成不依赖这些改动。
9. **没有任何实验结果**：本文的数字要么引自已核实的来源，要么标为【设计选择】或【估计】；示例都是假想的。
