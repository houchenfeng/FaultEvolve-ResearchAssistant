# 伐谋对照实验方案

> 目的：在**完全相同**的数据、评价指标、初始解和迭代预算下，比较百度伐谋与 FaultEvolve 的进化程度。
> 伐谋对照包：`benchmark/hdd_mvp/`（即 FaultEvolve MVP 使用的同一个基准目录）

---

## 1. 公平性控制

| 控制项 | 设置 |
|---|---|
| 数据 | 同一份 `data/public`（train + val）和 `data/eval_only/val_labels.csv` |
| 评估器 | 同一个 `evaluator.py`（伐谋标准接口），ROS 公式一致 |
| 初始解 | 同一个 `init.py`（val ROS 22.81） |
| 任务描述 | 同一份 `problem.md` 与 `prompt.md` |
| 迭代预算 | `max_iterations: 50`（伐谋 `config.yaml` 与 FaultEvolve `evolve.yaml` 相同） |
| 裁决 | 双方最优解都在本地用 `python evaluator.py <best.py> --split test` 评分；私有测试集不上传任何平台 |
| 重复 | 条件允许时每个系统跑 3 次，报告均值 ± 标准误 |
| 大模型 | 伐谋使用其平台默认模型；FaultEvolve 使用千问生成、Jev 评判，记录模型版本与 Token。结论中注明两者模型不同，这是系统层面的对比 |
| 评估位置 | 伐谋普通版在其云端运行评估器；FaultEvolve 在本地 worker 运行。评估器代码与数据相同，分数口径一致 |

## 2. 交付给伐谋的文件

```
benchmark/hdd_mvp/
├── problem.md          任务契约（伐谋 problem.md 模板结构）
├── evaluator.py        评估器：evaluate(path_user_py, task_name, timeout) -> {validity, combined_score, cost_time, error_info, metric}
├── init.py             初始解
├── prompt.md           进化系统提示（< 100 行）
├── config.yaml         伐谋实验配置（hybrid，max_iterations: 50；仅企业版混合云使用）
├── FAMOU_任务说明.md    网页端提交用：上传清单 + 直接模式指令（普通版使用）
├── candidates/rule_baseline.py   双候选验证的对照解
└── data/
    ├── public/         train_history.csv.gz, train_labels.csv, val_history.csv.gz, val_index.csv
    ├── eval_only/      val_labels.csv（评估器使用，候选程序不可见）
    └── meta.json
```

**不要上传** `data/holdout/` 与 `data/holdout_labels/`（已在 `.gitignore` 中排除）。

## 3. 提交步骤

### 3.1 普通版或进阶版（网页端，当前账号使用此方式）

1. 在伐谋专业版新建任务。
2. 上传 `benchmark/hdd_mvp/FAMOU_任务说明.md` 中列出的 10 个文件（4 个工件 + 6 个数据文件，文件名不变，扁平上传即可）。
3. 把 `FAMOU_任务说明.md` 中的「直接模式指令」整段粘贴发送；如果伐谋发起澄清，按 `problem.md` 回答，并强调「评估器和初始解原样使用」。
4. 确认执行卡片后开启深度演化，50 轮。
5. 每 10 轮询问一次进度并截图记录；结束后下载 Top 3 代码与报告。

注意：网页端模式下，数据和评估器会上传到伐谋云端运行。Backblaze 是公开数据，没有合规问题，但与 FaultEvolve 的「本地评估」模式不同，需在报告中注明。私有测试集**不上传**。

### 3.2 企业版（混合云，如后续升级账号）

在支持 Skill 的 Coding Agent 中安装 Famou Skills，然后在 `benchmark/hdd_mvp/` 目录下：

```bash
pip install famou-sdk==2.5.0
famou-ctl test --config ./config.yaml --timeout 900 --json     # 本地预演
# 预演通过后，从 config.yaml 删除 evaluator 行
famou-ctl experiment create --config ./config.yaml --experiment-name hdd_mvp_famou --dry-run --json
famou-ctl experiment create --config "$(pwd)/config.yaml" --experiment-name hdd_mvp_famou -y --json
mkdir -p .famou && : > .famou/eval_trace
nohup famou-ctl evaluator start --experiment-id <id> --evaluator-path ./evaluator.py --max-concurrent=1 \
  > .famou/eval_trace 2>&1 & echo $! > .famou/evaluator.pid
```

也可以直接对 Agent 说：「使用 famou-experiment-manager，以混合云模式提交当前目录的实验，50 轮。」

## 4. 需要记录的数据

| 指标 | 伐谋 | FaultEvolve |
|---|---|---|
| 最终 val ROS（平台报告的最优 combined_score） | | |
| 最终 test ROS（本地私有裁决） | | |
| test 上的 F1 / precision / recall / 误告率 / 漏告率 | | |
| 达到 ROS ≥ 28、≥ 30、≥ 32 所需轮次 | | |
| 有效候选率（validity=1 的比例） | | |
| 总耗时（墙钟） | | |
| 资源点 / Token 消耗 | | |
| 最优解运行时间（秒） | | |
| 最优解的主要策略（人工阅读代码后总结） | | |

每 10 轮保存一次伐谋排行榜快照（例如「查 Top 5 并保存」），用于绘制「最优分-轮次」曲线；实验结束后下载 Top 3 代码与 PDF 报告，放入 `resources/famou_runs/<experiment_id>/`。

## 5. 私有测试集裁决

```bash
cd benchmark/hdd_mvp
python evaluator.py resources/famou_runs/<id>/best.py --split test > build/famou_test.json
python evaluator.py <faultevolve_best.py> --split test > build/faultevolve_test.json
```

私有测试集只存在于本地；如果团队成员本地没有，可用 `prepare_data.py` 从 Backblaze 原始数据确定性重建（采样使用固定哈希种子）。

## 6. 结论撰写模板

1. 最终效果：test ROS 与各分项，val/test 间隙（过拟合程度）。
2. 进化效率：达到各分数档所需的轮次和时间，以及曲线。
3. 成本：资源点或 Token、墙钟时间。
4. 方案差异：双方最优解的核心策略对比，以及 FaultEvolve 中知识卡片和跨枝经验的贡献。
5. 局限：大模型不同、伐谋内部参数不可控、重复次数有限。
