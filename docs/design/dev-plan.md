## 4. 主仓库需要的改动（基于 SCHEMA_NOTES §10）

> 以下建议仅供参考，由用户和主仓库维护者决定是否实施。

### 4.1 阻塞项（答辩前必须）

| 改动 | 目的 | 位置 | 紧急程度 |
|------|------|------|---------|
| **修复 `repair_count` NameError** | 避免修复路径抛异常 | `engine.py` lines 450, 459 | **阻塞** |

### 4.2 建议改动

| 改动 | 目的 | 紧急程度 |
|------|------|---------|
| tree.json 增加 `adopted_cards` 字段 | 展示知识卡引用 | 中（可从 fe.db 补充） |
| 事件增加复合唯一索引 | 防止重复事件 | 低 |
| 增加可选 HTTP API 模式 | Sidecar 通信 | 低（可用 fe.db 轮询替代） |
| 节点 program 压缩 | 减少存储 | 低 |

### 4.3 不依赖主仓库改动的方案

| 场景 | 应对方案 |
|------|---------|
| `repair_count` 未修复 | 使用 `--mock` 模式或预录数据回放演示 |
| 无法跑真实 Qwen 流程 | 准备完整示例输出（tree.json, events.jsonl, fe.db）用于回放 |
| tree.json 缺少 adopted_cards | 前端从 fe.db `node_adopted_cards` 表补充读取 |
| 实时模式无 HTTP API | 采用 fe.db 轮询方案（已在设计中实现） |

## 5. 风险与应对

### 5.1 技术风险

| 风险 | 影响 | 应对 |
|------|------|------|
| **`repair_count` NameError（已确认）** | 修复算子路径抛异常，长跑中断 | **阻塞项**：主仓库 `engine.py` lines 450, 459 必须修复后才能跑完整流程 |
| 主仓库为私有仓库 | 本项目无法直接克隆或集成访问 | 通过源码附件获取数据结构，运行时需用户本地部署引擎 |
| events.jsonl 只在运行后写出 | 实时模式无法 tail 事件文件 | 改用 fe.db 轮询（已在设计中体现） |
| React Flow / D3 学习成本 | 演化树可视化延期 | 备选方案：简化为列表 + 缩进展示 |

### 5.2 已确认的主仓库缺陷

| 缺陷 | 位置 | 影响 | 状态 |
|------|------|------|------|
| `repair_count` 未定义 | `engine.py` lines 450, 459 | `_attempt_repair` 方法引用未定义变量，修复路径抛 NameError | **主线待修复** |

```python
# 问题代码片段（engine.py:450, 459）
if repair_count >= max_repairs:  # ← NameError
    ...
```

> **建议**：主仓库维护者在答辩前优先修复此缺陷，否则演示只能使用 `--mock` 模式或预录数据回放。

### 5.3 时间风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 答辩前功能未完成 | 无法演示 | MVP 范围严格控制，P2/P3 延后 |
| 主仓库 `repair_count` 未修复 | 无法跑完整流程 | 使用 `--mock` 模式或预录数据回放 |
| 真实 Qwen 运行数据未产出 | 只能用 Mock 数据演示 | 录屏兜底 + 流程演示 |
| 前后端联调问题 | 集成延期 | 9/30 开始并行开发，每日联调 |

### 5.3 许可风险

| 风险 | 影响 | 应对 |
|------|------|------|
| Navivisor 基于 AGPL-3.0 | 新仓库可能需要 AGPL | 咨询用户：接受 AGPL 或重写不复用的部分 |
| SmartMem 数据许可 | 赛后研究是否需再授权 | 标注"待核"，使用前确认条款 |
| Backblaze 数据使用条款 | 商用限制 | 当前为学术研究，符合条款 |
